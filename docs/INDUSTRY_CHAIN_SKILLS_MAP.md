## 一、产业链全景（14 节点）

```
                    ┌──────────────────────────────────────────────────┐
                    │              针织服装产业链全景                    │
                    └──────────────────────────────────────────────────┘

上游（原料端）                    中游（制造端）                   下游（流通端）
─────────────────────────────────────────────────────────────────────────────

①棉花/化纤贸易  →  ②纺纱厂  →  ③织造/针织厂  →  ④染整厂  →  ⑤成衣厂
     │                │              │              │            │
     ▼                ▼              ▼              ▼            ▼
⑥辅料/配件商    ⑦裁剪缝制    ⑧后整理       ⑨质检/检品    ⑩仓储物流
     │                                              │            │
     ▼                                              ▼            ▼
⑪品牌/零售终端  ←  ⑫海关/贸易  ←  ⑬金融/保险  ←  ⑭回收/可持续
```

| 节点 | 典型企业 | 核心角色 | 核心痛点 |
|------|---------|---------|---------|

| ②纺纱 | 纺纱厂、纱线贸易商 | 采购、生产计划 | 原料成本传导、产能利用率 |

| ④染整 | 染厂、印花厂 | 生产、环保 | 染化料成本、排放合规 |
| ⑤成衣 | 富泉等 OEM/ODM 工厂 | 老板、销售、采购、生产 | 接单、交期、良品率 |
| ⑥辅料 | 拉链/纽扣/标签供应商 | 销售、库存 | 小批量、快速交付 |

## 二、产业链 × Skills 传导网络

### 2.1 原料价格传导链

```
棉花价格 +3% 的跨节点传导：

①棉花贸易商                    立即感知（价格发现者）
  Skills: fetch_world_bank + causal_dag
  ↓ 0-2 周

②纺纱厂                       纱线报价上调（滞后 2 周）
  Skills: trend_forecast + risk_assessor + obsidian_writer
  ↓ 2-4 周

③织造/针织厂                   面料成本上升（滞后 4 周）
  Skills: fetch_comtrade_flow + scenario_predict
  ↓ 4-6 周

④染整厂                       染化料联动（滞后 1 周，独立变量）
  Skills: fetch_fred_observation + causal_dag
  ↓ 6-8 周

⑤成衣厂（富泉）                接单报价需调整
  Skills: counter_evidence_search + scenario_predict + obsidian_writer
  ↓ 3-6 月

⑪品牌方（优衣库）               零售价可能上调
  Skills: websearch_舆情 + scenario_predict
```

### 2.2 汇率传导链

```
日元贬值 5% 的跨节点影响：

①棉花贸易商    以美元计价，无直接影响
②纺纱厂       进口设备折旧成本降（日元计价）
③成衣厂       对日出口收入降 5%（日元换算人民币减少）
⑫海关/贸易    结汇时机选择
⑬金融/保险    汇率对冲需求
⑪品牌方       日本市场采购力变化

Skills 路径：
  fetch_fred_observation → causal_dag → scenario_predict → obsidian_writer
  每个节点的角色不同，但底层 Skills 相同
```

### 2.3 订单波动传导链

```
优衣库砍单 30% 的跨节点影响：

⑪品牌方（优衣库）    库存压力 → 砍单
  Skills: websearch_舆情 + fetch_hkex_pdf
  ↓ 立即

⑤成衣厂（富泉）      接单下降 → 产能闲置
  Skills: causal_dag + scenario_predict + obsidian_writer
  ↓ 1-2 月

④染整厂              订单减少 → 染缸利用率降
③织造厂              订单减少 → 织机停台
②纺纱厂              订单减少 → 纱线库存积压
①棉花贸易商          需求下降 → 棉花价格承压
⑥辅料商              订单减少 → 辅料库存积压

Skills 路径：
  fetch_comtrade_flow（优衣库进口数据）
  → causal_dag（为什么砍单）
  → scenario_predict（3 场景：维持/恶化/恢复）
  → counter_evidence_search（反证：有没有好转迹象）
  → obsidian_writer（写入决策建议）
```

## 四、产业链级工作流（跨节点联动）

### 4.1 全链路价格预警

```
触发：棉花价格变化 >3%

执行链路：
  ① 采集棉花价格（fetch_world_bank + Cotlook）
  ② 计算传导率（causal_dag + 节点间滞后系数）
  ③ 预测各节点影响（scenario_predict × 6 个节点）
  ④ 写入 Obsidian（每个节点一份预警报告）
  ⑤ 通知受影响最大的节点角色

参与角色：Collector × 2 + Reasoner × 2 + Predictor × 1 + Writer × 6
成本：~¥3/次
```

### 4.2 客户砍单全链路影响分析

```
触发：fetch_comtrade_flow 发现客户国进口下降 >10%

执行链路：
  ① 确认下降趋势（fetch_comtrade × 3 个月）
  ② 分析原因（causal_dag：库存/汇率/政策/竞争）
  ③ 反证搜索（counter_evidence_search：有没有反面信号）
  ④ 评估影响（scenario_predict：对成衣厂/纺纱厂/原料商的影响）
  ⑤ 写入 Obsidian（按节点分报告）

参与角色：Collector + Reasoner + Devil + Predictor + Writer
成本：~¥5/次
```

### 4.3 关税/政策变动全链路评估

```
触发：websearch 发现 HS 编码关税公告

执行链路：
  ① 抓取政策原文（websearch + RSS）
  ② 分析影响范围（causal_dag：哪些 HS 编码、哪些节点）
  ③ 评估成本变化（fetch_fred_observation + trend_forecast）
  ④ 反证（counter_evidence_search：有没有豁免/替代方案）
  ⑤ 写入 Obsidian（按节点分报告 + 建议行动）

参与角色：Collector + Reasoner + Devil + Predictor + Writer
成本：~¥5/次
```

### 4.4 供应链中断全链路响应

```
触发：websearch 发现港口拥堵/物流延误

执行链路：
  ① 确认中断信息（websearch + vessel tracker）
  ② 评估影响范围（causal_dag：哪些航线、哪些货物）
  ③ 计算库存缓冲（watch_excel_file：各节点库存天数）
  ④ 建议替代方案（scenario_predict：空运/替代港口/延迟交货）
  ⑤ 写入 Obsidian（紧急预警 + 行动清单）

参与角色：Collector + Reasoner + Predictor + Writer
成本：~¥3/次
```

## 五、产业链级自进化

### 5.1 跨节点学习

```
一个节点的发现可以帮到整条链：

  ⑤ 成衣厂发现：优衣库砍单是因为日本库存高
       ↓ 写入 Obsidian
  ① 棉花贸易商看到：优衣库砍单 → 未来棉花需求可能下降
       ↓ 调整采购策略
  ② 纺纱厂看到：成衣订单减少 → 纱线需求将下降
       ↓ 减少产能
  ③ 织造厂看到：同上 → 减少织机开台

这就是产业链级的自学习：
  一个节点的 causal_dag 发现 → 通过 Obsidian 共享 → 影响整条链的决策
```

### 5.2 产业链级监控

```
监控指标 = 产业链健康度指数

原料端：棉花价格波动率、化纤开工率
制造端：纺纱开机率、织造开机率、染整产能利用率、成衣接单指数
流通端：港口吞吐量、船期准时率、库存周转天数
终端：品牌同店销售、电商 GMV、消费者信心指数

每个指标 = 一个 fetch_* 技能
产业链健康度 = f(所有指标的加权和)
```

### 5.3 产业链级自进化

```
普通自进化：技能 A 表现差 → 换成技能 B
产业链级自进化：

  发现：fetch_comtrade_flow 对日本海关数据的准确率只有 72%
         但对韩国海关数据的准确率有 94%
       ↓
  原因：日本海关 Excel 格式经常变，Playwright 解析不稳定
       ↓
  解决：生成新技能 fetch_japan_customs_api（调 API 而非抓 Excel）
       ↓
  验证：sandbox 测试 5 天，准确率提升到 91%
       ↓
  上线：自动替换旧技能
       ↓
  整条链受益：所有需要日本海关数据的节点（成衣/品牌/海关/金融）都用上新技能
```

## 六、修正后的实施路径

### Phase 0（Week 0）：MCP 安全加固
```
与之前相同：mcp-scan + 沙箱 + 致命三角隔离
```

### Phase 1（Week 1-2）：单节点 MVP
```
选 1 个节点（⑤ 成衣厂/富泉）
选 1 个角色（老板）
选 1 个工作流（每日简报）
用 2 个 A 级 MCP 跑通
验证：老板明天早上 8 点能看到棉花价格 + 客户动态
```

### Phase 2（Week 3-4）：单节点扩展
```
扩展到 ⑤ 成衣厂的 4 个角色（老板/销售/采购/生产）
上线 3 个工作流（每日简报 + 价格异动 + 客户健康度）
验证：4 个角色都有价值
```

### Phase 3（Week 5-8）：相邻节点
```
扩展到 ① 原料端 + ⑪ 品牌端
用产业链传导链连接 3 个节点
验证：原料价格变动 → 成衣厂 → 品牌方的传导可见
```

### Phase 4（Week 9-12）：全链路
```
扩展到 14 个节点
上线产业链健康度指数
验证：整条链的因果关系可追溯
```

### Phase 5（Week 13+）：自进化
```
上线监控层 + 思考层 + 进化层
跨节点学习开始运转
验证：一个节点的发现自动帮助其他节点
```

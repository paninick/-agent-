## 一、用户身份与场景

### 1.1 用户画像

```
身份: 富泉纺织 (南通) 相关方
  - 可能是老板/销售总监/采购经理/生产厂长
  - 行业: 针织服装出口制造
  - 规模: 中小型 (100-500 人)
  - 主营: 对日本/欧美的 ODM/OEM

痛点 (从对话推断):
  - 老板: 不确定下一季度该接什么单、该不该扩产
  - 销售: 不知道客户真实需求变化, 只能被动接单
  - 采购: 不知道原料该不该囤、什么时候买最划算
  - 厂长: 不知道产能瓶颈在哪、该不该升级设备

核心矛盾:
  - 缺乏第一手数据 (看新闻/行业说法, 没有自己的数据)
  - 缺乏全局视野 (只看自己工厂, 不知道上下游)
  - 缺乏因果能力 (知道发生了什么, 不知道为什么)
  - 缺乏预测能力 (只能事后总结, 不能事前判断)
```

### 1.2 使用场景

```
高频场景 (每天):
  - 看告警: "今天有影响我的重大事件吗?"
  - 看仪表板: "我现在的处境怎么样?"

中频场景 (每周):
  - 周报: "这周发生了什么变化? 我该怎么调整?"
  - 客户分析: "X 客户接下来会怎么变化?"

低频场景 (每月/每季):
  - 战略复盘: "过去一个月我的判断对了吗?"
  - 年度计划: "明年我应该怎么布局?"
```

## 二、核心需求 (按优先级)

### P0 - 必须实现

#### 2.1 全链路因果推导

```
需求: 从原料价格波动到企业接单决策的完整推导链
输入: 棉花期货涨 12%
输出: 富泉是否该囤料、报价怎么调、客户会怎么反应、3 个月后会发生什么

具体场景:
  - 棉花涨 → 中国 HS60 面料涨 → 越南工厂成本涨 → 越南 HS61 FOB 涨
  - 美国对越南加关税 → 美国买家转单孟加拉/中美洲
  - 优衣库库存积压 → 优衣库砍单 → 中国/越南工厂接单减少

约束:
  - 每个数据点必须有源可查
  - 每个计算必须有可重现公式
  - 每个结论必须有反证空间
```

#### 2.2 实体颗粒度建模

```
需求: 不停在"品牌 X 越南占比多少"，要追到具体工厂的产能、设备、配套
输入: 优衣库新增 3 家越南工厂
输出:
  - X 工厂: 股权结构、设备清单、面料来源、配套产能
  - Y 工厂: 同上
  - Z 工厂: 同上
  - 区域配套约束: 纸箱/染整/物流瓶颈
  - 真实有效产能 vs 理论产能

必须追问的字段:
  - 注册名 / 地址 / 股权 / 母公司 / 实控人
  - 设备清单 / 产能 / 瓶颈 / 利用率
  - 面料来源 (国家 + 比例) / 辅料 / 包材
  - 配套环境 (工业区 / 港口 / 检测)
  - 客户 / 合规 / 风险

数据来源:
  - OS Hub: 限制使用 (新用户需等待) → 备用源
  - 企查查 / 天眼查 (已接入)
  - 海关数据 (Comtrade 已验证)
  - 实地调研 (标注: 数据缺口)
```

#### 2.3 数字验证网络

```
需求: 每个数字能沿着链条验证到底
方法: 上游-下游-平行 三方验证

示例链路 (优衣库基础 T 恤):
  优衣库天猫 T 恤价格×数量 → 推算销售额
    vs 迅销年报品类营收 → 对得上吗?
    vs 日本海关 HS6109 从中国进口 → 量级对吗?
    vs 申洲年报 (优衣库占比×营收) → 供货额对吗?
    vs 中国海关 HS6109 对日出口 → 镜像对吗?
    vs 面料消耗推算 (件数×克重) → 面料总需求合理吗?
    vs 柯桥面料价格×数量 → 成本估算 vs FOB vs 毛利率 → 闭环吗?

规则:
  - 对不上 ≠ 错误, 对不上 = 发现异常 = 分析价值
  - 必须输出"已对账"和"待对账"两类结论
```

#### 2.4 数据缺口管理

```
需求: 知道自己不知道什么
输出: 数据缺口清单 + 重要性排序 + 填补路径

示例:
  [DATA_GAP] 越南本地 HS60 产能数据
    重要性: ★★★★★ (直接影响越南对中国依赖度判断)
    填补路径:
      ① WebSearch VITAS 2024 年报 (B 级源, 1 天)
      ② 申请越南海关企业级数据 (付费, 1 个月)
      ③ 实地调研 (行业渠道, 1 个月)

原则:
  - 缺失就明确说"不知道"
  - 列出填补路径, 不假装能猜
  - 评估缺口对当前结论的影响
```

### P1 - 重要但可分阶段

#### 2.5 品牌画像完整化

```
需求: 把品牌 (优衣库、H&M、Zara 等) 的所有维度都建成可查表
维度:
  - 商业模式: 定位、价格带、SKU 数量、品类结构、上新节奏
  - 财务: 营收、毛利率、库存、应收、应付、现金流
  - 供应链: 供应商数、国家分布、Tier 分层、面料来源、交期、MOQ、付款条件
  - 采购: 季度节奏、面料提前量、补单反应、新供应商导入
  - 用户: 人群、复购率、客单价、退货率、价格敏感度
  - 战略: 战略方向、隐含供应商需求
  - 决策人: CEO、供应链 SVP、采购总监 (公开可查的)

每个维度都必须声明:
  - 数据来源 (一手 vs 推算)
  - 时间戳
  - 历史变化趋势
  - 验证方式
```

#### 2.6 行业基准参数库

```
需求: 每个细分赛道的"正常值", 偏离多少算异常
示例 (针织 T 恤):
  库存周转天数: 60-90 天 健康, 90-120 警戒, >120 危险
  面料占 FOB: 40-55% (品类不同有差异)
  越南 vs 中国价差: 5-15% (关税 + 灵活性溢价)
  棉花传导率: 70-80% (历史拟合)

使用:
  - 偏离 2σ 自动触发分析
  - 季度校准基准
```

#### 2.7 潜伏触发机制

```
需求: 有事才通知, 无事静默
触发层级:
  Level 0: 心跳探针 (HTTP HEAD), 零成本
  Level 1: 阈值检测 (规则引擎), 零成本
  Level 2: 快速评估 (Flash 模型), ~¥0.06
  Level 3: 完整分析 (Opus 模型), ~¥2

规则配置:
  棉花价格变化 > 3% → Level 2
  越南 HS60 进口异常 > 2σ → Level 2
  优衣库供应商名单变化 → Level 3
  客户财报库存 > 100 天 → Level 2

通知方式:
  高紧急 → 飞书/微信 即时
  中紧急 → 每日汇总
  低紧急 → Obsidian 周报
```

#### 2.8 社交信号网络

```
需求: 从公开渠道追踪关键人物, 推断品牌动作
合法边界:
  ✓ 公开发布的帖子/动态
  ✓ 公开活动参与
  ✓ 公开关注列表变化
  ✗ 私信/私密内容
  ✗ 未经授权爬取 (违反平台 ToS)

目标对象:
  - 品牌采购总监 / 供应链 SVP
  - 关键面料/成衣业务负责人
  - 竞品企业高管
  - 行业协会负责人
  - 园区/政府招商负责人

信号处理:
  本人发文 = A 级信号
  同事/朋友发文 = B 级信号
  行业群讨论 = C 级信号
  多源交叉 = 升级信号等级
```

### P2 - 锦上添花

#### 2.9 多 Agent 编排

```
需求: 多个 Agent 分工协作
角色:
  - 调度者 (Orchestrator): 决定任务分派
  - 采集员 (Collector): 多源拉取
  - 清洗员 (Cleaner): 单位/口径/异常处理
  - 权重员 (Weigher): 综合权重计算
  - 推理员 (Reasoner): 因果推导
  - 验证员 (Devil's Advocate): 对抗验证
  - 预测员 (Predictor): 场景模拟
  - 记录员 (Writer): 分级写入

实现方式:
  - DeepSeek 自动生成初版代码
  - Claude 审核
  - 跑通测试 → 入库
```

#### 2.10 自动化部署

```
需求: 无人值守运行
部署选项:
  - Windows 任务计划 (本地 cron)
  - GitHub Actions (云端 cron)
  - AutoClaw Docker (无头并发)
  - Vercel / Railway (轻量部署)

备份机制:
  - 探针失败 → 重试 → 备用源 → 跳过
  - 关键任务 → 失败告警 → 手动兜底
```

## 三、数据源硬约束（最重要）

### 3.1 排除付费 / 受限数据源

```
排除:
  ✗ ImportGenius - 付费 ($99-399/月) → 用替代方案
  ✗ Panjiva - 付费 ($400+/月)
  ✗ Factiva / Brand24 - 付费
  ✗ Open Supply Hub API Key - 新用户审批延迟 → P1 标记为受限
  ✗ D&B / 商业征信数据 - 付费
```

### 3.2 优先级：免费 + 第一手 + 真实 + 不污染

```
S 级：政府/交易所/公司的原始一手数据
  - 已实测: UN Comtrade (Free Key × 2)
  - 已实测: FRED (Free Key)
  - 已实测: SEC EDGAR (免费)
  - 已实测: Eurostat (免费)
  - 已实测: BLS (免费)
  - 待对接: 世界银行 / 国际货币基金 / 国际劳工组织
  - 待对接: 海关总署 (中国/日本/越南/孟加拉/印尼)
  - 待对接: USITC / USTR (美国关税)
  - 待对接: EDINET (日本财报)

A+ 级：上市公司的合规披露
  - 已实测: Massive.com (Free Key, 美股 NKE/LULU/TJX 等)
  - 已实测: 通达信 MCP (港股财报/研报)
  - 待对接: EDINET (日企财报)

A 级：行业协会 / 权威机构
  - 已接入: 企查查 MCP
  - 已接入: 天眼查 MCP
  - 待对接: VITAS (越南纺织协会)
  - 待对接: JETRO (日本贸易振兴机构)
  - 待对接: 中国纺织工业联合会
```

### 3.3 数据真实性高于数量

```
原则: 
  - 5 条真实数据 > 100 条推算数据
  - 宁可空白不填, 不能填可疑数据
  - 与其追求数据广度, 不如抓验证深度
  - 任何"未验证"的数据, 在推导中只能用 B 级源代号

"不污染"清单:
  ✗ 任何来源不明的群消息
  ✗ 任何未署名的转载文章
  ✗ 任何无日期来源的数据
  ✗ 任何"听说 / 据传 / 业内人士"
  ✗ 任何未公开的内部数据（哪怕"业内通用"）
```

### 3.4 受限数据源的替代方案

```
Open Supply Hub (受限) 的替代:
  - 工厂规模、产能：海关设备进口数据反推
  - 工厂画像：企查查/天眼查 + 海关 + 招聘平台
  - 工厂-品牌关联：品牌供应商名单（公开部分）+ 海关提单

ImportGenius (付费) 的替代:
  - 美国市场进出口：USITC + Census + ITA
  - 企业级提单：定时观察公开提单样本
  - 企业画像：10-K 提到的供应商 + 财报披露

孟加拉海关 (无 Comtrade) 的替代:
  - BGMEA 协会数据（B 级）
  - World Bank 孟加拉贸易报告（B 级）
  - 实地调研渠道（行业人脉）
```

## 四、不做什么 (明确边界)

### 4.1 不做实时数据

```
不做:
  - 实时分钟级价格
  - 实时库存
  - 实时订单状态

原因:
  - 不是核心需求
  - 实时数据成本高
  - 滞后 1-3 天的数据足以做决策
```

### 4.2 不做客户内部数据

```
不做:
  - 富泉的客户名单 (L3 机密)
  - 富泉的成本细节
  - 富泉的合同条款
  - 富泉的人员信息

替代:
  - 用脱敏版本演示
  - 用行业平均替代
  - 用公开数据替代
```

### 4.3 不做企业内部运营系统

```
不做:
  - ERP
  - 库存管理系统
  - 客户管理系统
  - 财务系统

原因:
  - 这是工具, 不是系统
  - 用户已经有自己的系统 (RuoYi-Vue ERP)
  - 我们做的是情报 + 决策支持, 不做日常运营
```

## 五、成功定义

### 5.1 用户视角的成功

```
用户在以下场景能获得价值:
  ① 看棉花涨价 → 知道该不该囤料 (30 秒内)
```

```
技术 KPI:
  - 数据覆盖度 > 80%
  - 数据新鲜度 < 30 天 (核心指标)
  - 自动化率 > 80%
  - 探针成功率 > 95%
  
业务 KPI:
  - 结论准确率 > 70%
  - 决策采纳率 > 50%
  - 用户反馈 NPS > 40
  - 月成本 < ¥900
```

## 六、约束 (不能违反的硬规则)

### 6.1 数据真实性

```
任何数值断言必须:
  - 标注来源 (URL/API/Key)
  - 标注时间戳
  - 标注等级 (S/A+/A/B+/B/C)
  - 标注完整度

不能:
  - 用行业说法代替实测
  - 把推算说成已知
  - 忽略反证
```

### 6.2 数据安全

```
API Key / 凭据:
  - 永不入代码
  - 永不写入代码注释
  - 永不上传到任何云端
  - 永不在日志中明文打印
  
敏感数据:
  - L2 仅本地
  - L3 仅本地加密卷
  - 客户清单/成本/合同不入 ima
```

### 6.3 成本控制

```
月度总预算 ¥900:
  - Agent Plan ¥200 (固定)
  - 按量 API ¥100 (备用)
  - Claude Code (在订阅中)
  - DeepSeek 免费额度 ¥0
  - Comtrade 免费 ¥0
  - FRED 免费 ¥0
  - Massive.com 免费 ¥0
  - 应急 ¥550

任何调用前必须检查:
  - L0/L1 → 优先免费额度
  - L2/L3 → 优先 Claude 或 Plan 窗口
  - 全部超限 → 排队或降级
```

### 6.4 真实性原则

```
绝不:
  - 编造数据
  - 假装验证通过
  - 隐瞒反证
  - 用"行业共识"替代实测
  - 省略前提条件
  
必须:
  - 标注所有假设
  - 列出所有数据缺口
  - 给出反证空间
  - 给出边界条件
```

## 十、风险与缓解

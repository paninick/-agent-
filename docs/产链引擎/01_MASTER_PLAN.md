## 一、核心定义

### 1.1 系统本质

**产链引擎 = 产业链信源验证与传导分析系统**

不是工具，不是数据看板，不是聊天机器人。

是一个**数据可追溯验证网络**：
- 把品牌、工厂、原料、价格、关税、人流、物流的所有公开数据点连成网
- 每个点都能被它的上游、下游、平行点交叉验证
- 对不上的地方 = 发现异常 = 分析价值的所在

### 1.2 价值主张

| 现有工具 | 产链引擎 |
|---|---|
| 通达信：单一维度金融数据 | 六维交叉：财务+海关+供应商+平台+物料+合规 |
| 企查查：单点企业信息 | 实体关系图谱：品牌↔工厂↔面料商↔原料商 |
| Bloomberg：宏观 + 单企业 | 跨行业 + 跨企业 + 跨地域的传导分析 |
| 咨询公司 (BCG/麦肯锡)：6人×8周交付 PPT | 7×24 持续运行 + 数据缺口管理 + 实时修正 |

### 1.3 核心差异化

1. **第一信息源优先**：海关/财报/官方 API > 行业研报 > 新闻
2. **数据可追溯验证网络**：每个数字可追溯、可交叉、可对账
3. **数据缺口管理**：知道自己不知道什么
4. **传导分析**：从原料价格波动推到企业接单决策
5. **战略输出**：不止数据，给方案、给路径、给退出条件

## 二、系统架构

### 2.1 七层架构

```
Layer 7: 战略输出层 (Strategic Output)
  └── 行动方案、风险预警、机会识别、退出机制
Layer 6: 验证层 (Verification)
  └── 多路径验证、Devil's Advocate、边界条件、历史类比
Layer 5: 拟合层 (Modeling)
  └── 成本模型、敏感性分析、场景模拟、时间线推演
Layer 4: 论证层 (Argumentation)
  └── 传导网络（多路径+反馈环）、反证、置信度评分
Layer 3: 分析层 (Analysis)
  └── 趋势识别、相关性分析、结构性变化检测、竞争格局变化
Layer 2: 清洗层 (Cleaning)
  └── 单位标准化、口径对齐、异常检测、实体消歧、时间修正
Layer 1: 采集层 (Collection)
  └── 多源并行、来源等级标记、时间戳、口径声明、TTL 标注
```

### 2.2 七角色体系

| 角色 | 职责 | 输入 | 输出 |
|---|---|---|---|
| **Collector** (采集员) | 多源拉取原始数据 | 触发信号 + 目标实体 | 原始数据包 + metadata |
| **Cleaner** (清洗员) | 单位/口径/异常处理 | 原始数据 | 标准化证据条目 |
| **Weigher** (赋权员) | 权重计算 + 交叉验证 | 标准化证据 | 加权证据 + 置信度 |
| **Reasoner** (推理员) | 传导分析 + 结论 | 加权证据 | 传导网络 + 反证 + 结论 |
| **Devil's Advocate** | 对抗性验证 | 结论 + 证据链 | 验证报告 (PASS/WARN/FAIL) |
| **Predictor** (预测员) | 场景模拟 + 时间线 | 已验证结论 | 场景矩阵 + 概率分布 |
| **Writer** (记录员) | 多层写入 | 所有阶段产出 | Obsidian/Ark/IMA 分级写入 |

### 2.3 三层记忆架构

```
Layer A: Obsidian 本地 (权威源)
  - 全级别 (L0-L3) 数据
  - 加密卷 (VeraCrypt/BitLocker)
  - 人类可读 Markdown + 双链
  - 永不云同步
  - 容量无限

Layer B: Ark Memory / OpenViking (云端检索层)
  - L0-L1 数据 (脱敏后)
  - API 直接调用
  - 支持 TTL
  - 容量有限 (~3M token 免费)

Layer C: 向量库 (语义检索层)
  - L0-L1 数据嵌入
  - 相似品牌/供应商检索
  - 不精确，需要人工验证

写入规则：所有写入 → Obsidian (权威) → 同步到 B/C
读取规则：B/C 优先 → 不命中再查 Obsidian → 不命中再拉 API
```

## 三、关键约束 (Hard Constraints)

### 3.1 数据信源可靠性约束

```
★ 任何数值断言必须标注数据来源
  错误：FOB 出口价 $3.5/件
  正确：FOB $3.5/件 (来源: 中国海关 HS6109.10 对日出口平均单价)

★ 没有数据时明确标注为"数据缺口"
  错误：越南 60% 面料来自中国
  正确：[DATA_GAP] 越南面料对中国依赖度 = 需要 UN Comtrade HS60 数据
       间接估算来源: VITAS 2024 年报 (B 级源)

★ 计算过程中每个参数都要声明来源
  织物占比 45% → 来源：行业模型 (A 级源)
  传导率 70-80% → 来源：2022-2025 历史拟合 (A 级源)

★ 间接推导必须声明推导链和不确定度
  越南工厂面料成本变化 = cn_fabric_price_change × CN_share × fabric_in_fob
  关键参数 CN_share 来源等级 < A → 结论只能是"估算"
```

### 3.2 安全分层约束

```
L0 公开数据：任何模型可处理，无限制
L1 内部分析：脱敏后国内模型可处理
L2 商业敏感：本地或脱敏 + 加密后处理
L3 核心机密：仅本地，绝不外发

数据安全规则：
  ✗ API Key / Token / Secret 绝不发任何外部 API
  ✗ 客户名单/合同金额/真实供应商清单 仅本地
  ✗ 公司内部财务/成本细节 不上 ima
  ✓ 通用方法论/公开行业数据 可上 ima 知识库
```

### 3.3 成本控制约束

```
月度总预算 ¥900 (人民币)

  - 火山方舟按量 API: ¥100 (备用)

  - 通达信 MCP: 已在订阅

每调用前预算检查规则：
  - L0/L1 任务 → 优先免费额度 (DeepSeek V4 Pro / Doubao Pro 2.1 / GLM-4.7)
```

### Phase 2: 自动化脚本

**目标**：把手动 API 调用转为无人值守的 cron 任务

**内容**：
- 探针脚本 (cotton_probe.py, fx_probe.py, custom_probe.py)
- 解析器 (excel_to_json.py, html_to_evidence.py)

- 触发器 (signal_detector.py)
- 通知 (feishu_notifier.py, wechat_notifier.py)

**工具**：
- Python (核心脚本)
- AutoClaw (无头 Docker 部署)
- Windows 任务计划 (本地 cron)
- GitHub Actions (跨平台)

### Phase 3: DeepSeek 自动化生成 + Claude 审核

**目标**：建立人机协作的代码生成流水线

**流程**：
1. 用户/Claude 设计 SOP 和数据契约
2. DeepSeek 基于 SOP 生成初版代码
3. Claude Code 审核 (逻辑、错误处理、性能)
4. 自动跑测试 (用真实 API 验证)
5. 通过 → 入库；失败 → 反馈给 DeepSeek 重做

**适用场景**：
- 新的探针脚本
- 新的解析器
- 新的数据源 adapter

### Phase 4: 端到端验证

**目标**：跑通完整链路，证明"基于事实的计算"

**示例链路**：
```
棉花期货涨 12% (FRED/SEC)
  → 中国 HS60 面料出口单价涨 8% (Comtrade)
  → 越南 HS60 进口成本涨 5.5% (Comtrade × 依赖度)
  → 越南 HS61 FOB 成本涨 2.4% (面料占比 45%)
  → 美国进口越南 HS61 单价反映 (USITC/海关)
  → 品牌采购决策变化 (财报/招聘/供应商名单)
```

每个环节的数据都必须可验证、可追溯、可交叉。

## 五、核心 KPI (定义成功)

| KPI | 目标 | 测量方式 |
|---|---|---|
| **数据覆盖度** | 6 维度 × 主要市场 ≥ 80% | 自动探测每个维度的数据可得性 |
| **数据新鲜度** | 核心指标 < 30 天 | 每个证据条目的 timestamp 检查 |
| **结论准确率** | 回测 > 70% | 历史预测 vs 实际结果对比 |
| **数据缺口透明度** | 100% 缺口标注 | 任何结论必须标注 unknown 项 |
| **自动化率** | > 80% 的探针无人值守 | cron 任务失败次数 < 5%/月 |
| **成本控制** | < ¥900/月 | 实时用量监控 |
| **响应时间** | 紧急告警 < 5 分钟 | 从触发到通知的延迟 |

## 六、风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| API 政策变化 | 数据源突然失效 | 多源冗余 + 关键数据本地缓存 |
| 模型供应商政策变化 | 敏感数据被泄露 | L0-L3 分级 + 本地优先 |
| 数据缺口堵塞决策 | 无法形成完整结论 | 缺口管理 UI + 优先级排序 |
| 自动化任务崩溃 | 数据未更新 | 监控告警 + 重试机制 + 手动兜底 |
| 关键人物离职 | 项目停摆 | 全程文档化 + SOP 标准操作 |

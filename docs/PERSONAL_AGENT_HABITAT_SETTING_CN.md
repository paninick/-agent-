# Personal Agent Habitat / 个人 Agent 活动空间设定

## 1. 产品定义

Personal Agent Habitat 是面向个人用户、默认 24 小时持续运行的 Agent 操作空间。用户主要负责发布需求、确认目标与权限、回答 Agent 主动提出的问题以及接收成果；任务拆解、临时组队、工具调用、验证、重试、记忆沉淀和自动化安排由 Agent 自主完成。

它不是聊天机器人、固定十角色流水线或需要用户持续监控的企业控制台。

## 2. 核心体验承诺

用户重新打开产品时，应在十秒内回答四个问题：

1. 我的 Agent 现在正在做什么？
2. 它为什么这样做？
3. 有什么必须由我决定？
4. 我离开后完成了什么？

首页视觉顺序固定为：当前需求与活动小队 → 用户互动边界 → 24 小时成果回放。完整 DAG、模型调用、Token 与底层日志为按需展开的信息。

## 3. Agent 架构

### 3.1 常驻 Agent

- 管家：理解需求、维持长期关系、管理通知并交付结果。
- 规划者：把自然语言需求编译成目标契约，动态拆解任务并组建小队。
- 记忆者：保存用户确认过的偏好、成果、关系和可复用流程。
- 守门人：管理隐私、预算、权限和外部行动审批。

常驻 Agent 有稳定的身份色、轮廓、工具和空间位置。常驻不等于永远运行；待命时应保持低资源占用。

### 3.2 临时 Agent

临时 Agent 必须由具体目标或任务创建，声明需要的模型、技能、工具、预算、权限和销毁条件。完成任务后先将成果交给记忆者，再进入解散状态。相似任务可以根据记忆重新唤醒同一种能力，但不默认保留全部上下文与权限。

### 3.3 与现有十角色蜂群的关系

现有 Scout、Collector、Data Janitor、Verifier、Analyst、Devil's Advocate、Adjudicator、Reconciliation Scorer、Synthesizer、Memory 是一种可被动态小队调用的情报工作流模板，不是用户首页永久展示的十个角色。规划者可以整套调用、裁剪调用或将其中能力组合进临时 Agent。

## 4. 目标契约

每个用户需求必须编译为可确认的目标契约：

- 原始需求与期望结果。
- 成功指标、期限和预算。
- 已知假设与待澄清问题。
- 允许动作、禁止动作和自动化等级。
- 数据范围、隐私级别和外部渠道。
- 失败策略、回滚方式和完成条件。

信息不足时，规划者先回显“我理解的目标”，只询问真正影响结果的变量。

## 5. 动态组队与任务空间

任务空间使用任务核心、工作岛、证据包、用户边界和记忆区五种对象：

- 任务核心：一个活动目标的统一视觉锚点。
- 工作岛：围绕子目标临时形成的 Agent 小队。
- 证据包：Agent 间可传递、可查看来源和置信度的信息对象。
- 用户边界：澄清、选择、预算与外部行动必须跨越的控制面。
- 记忆区：已确认偏好、成果和规则的长期归档位置。

默认只展示当前活跃小队和关键依赖。完整任务图通过“展开工作路径”进入二级视图。

## 6. 用户互动协议

Agent 发起互动时必须说明：

- 为什么现在询问。
- 已尝试过什么。
- 推荐选择及理由。
- 支持与反对证据。
- 不回应的结果。
- 操作是否可撤销。
- 是否建议为未来相似情况授权。

用户可直接选择、修改条件、要求补证、暂缓、拒绝或设置以后自动处理。

## 7. 权限与自动化等级

1. 只观察：不可创建草稿或执行外部动作。
2. 准备草稿：可以整理内容，但发送前必须确认。
3. 每次询问：所有外部动作逐次审批。
4. 限额自动执行：仅在预算、收件人、时间和风险范围内执行。
5. 禁止：明确阻止某类能力、渠道或数据访问。

付款、发送消息、公开发布、删除数据、修改账户与不可逆操作默认需要守门人审批。授权必须带范围和到期时间。

## 8. 24 小时运行

- 早晨：生成夜间成果摘要和少量优先问题。
- 白天：允许快速发布需求、补充上下文和接管节点。
- 夜间：降低非必要活动频率，整理记忆、合并任务并预警预算。
- 用户返回：播放可跳过的活动摘要，而不是倾倒完整日志。

通知分为成果、问题、决定、权限四类。只有需要及时处理的决定与权限请求默认推送到外部渠道。

## 9. 拟人化与动画语言

拟人化通过姿态、距离、工具和交互行为表达，不使用真人脸、可爱机器人或游戏 NPC 话术。

- breathe：待命呼吸，仅表达在线。
- turn_to_need：常驻 Agent 转向新任务。
- materialize：临时 Agent 从具体子任务形成。
- approach_squad：加入工作岛。
- exchange_evidence：传递可追踪证据包。
- approach_user_boundary：携带问题走向用户边界。
- place_result_in_memory：把成果交给记忆者。
- dissolve：成果沉淀后自然解散。

动画必须可解释当前状态，并支持 reduced-motion。低动态模式使用透明度和位置过渡替代粒子、旋转和视差。

## 10. 视觉系统

- 墨蓝 `#101823`：主空间与夜间运行。
- 雾灰 `#D9E2E0`：信息层与白天模式。
- 矿物青 `#4BA89A`：探索、证据与安全完成。
- 群青 `#4E72D8`：规划与计算。
- 暖琥珀 `#E4A84B`：管家、关注与用户决定。
- 朱砂 `#C75A4A`：风险、冲突与越界动作。
- 月白 `#EDF2EF`：主要文本。

颜色首先表达身份和状态，不作为装饰。背景可借用抽象山水的层次与时间感，但不能牺牲文本对比度或让产品变成游戏场景。

## 11. 成果与记忆

所有目标必须产生一个可交付成果或明确的未完成原因。成果可以是文件、预订、提醒、消息、代码、报告或外部系统变更。

记忆只保存：用户明确确认的偏好、有证据的稳定事实、可复用程序和成果索引。推断性偏好必须显示来源、置信度和撤销入口。

## 12. 首期完成标准

- 用户能从自然语言创建并确认目标契约。
- 规划者能动态创建至少一个临时 Agent 和任务小队。
- 首页能解释当前活动、原因、进度和依赖。
- Agent 能以完整互动协议发起澄清或审批。
- 用户能设置限额自动化和撤销授权。
- 临时 Agent 完成后能交付成果、沉淀记忆并解散。
- 24 小时回放能过滤重要事件。
- 所有外部动作具有审批、审计、幂等和回滚说明。
- 动画具有 full、reduced 和 none 三种模式。

# 弹性系数计算方法（产业链因果链条专用）

> **版本**：v1.0 | **日期**：2026-07-01
> **目的**：量化产业链每条边的价格弹性，让因果 DAG 有真实的数字支撑

---

## 一、什么是弹性系数

```
弹性系数（Elasticity）= 需求变化% / 价格变化%

通俗解释：
  弹性 = -0.8 → 价格涨 10%，需求降 8%（消费者比较敏感）
  弹性 = -0.3 → 价格涨 10%，需求降 3%（消费者不太敏感）
  弹性 = -1.5 → 价格涨 10%，需求降 15%（消费者非常敏感）

产业链中的弹性不只是消费者弹性，还包括：
  边际弹性：上游涨价 X%，下游采购量变化 Y%
  交叉弹性：A 品涨价，B 品需求变化（替代效应）
  收入弹性：收入变化 X%，需求变化 Y%
```

## 二、产业链每条边的弹性计算公式

### 边 ①→②：原料内部交叉弹性

```
交叉弹性（棉花 vs 涤纶）= 涤纶需求变化% / 棉花价格变化%

计算方法：
  1. 找棉花价格变化数据（ICE 月度）
  2. 找涤纶开工率/产量变化数据（CCFEI 月度）
  3. 回归分析：涤纶产量 = α + β × 棉花价格
  4. β = 交叉弹性系数

Obsidian 可用数据：
  棉花：ICE 月度价格 ✅
  涤纶：CCFEI 开工率 → 待补
  → 缺口：涤纶月度开工率数据
```

### 边 ②→③：化纤→面料（成本弹性）

```
成本弹性 = 面料采购量变化% / 原料价格变化%

计算方法（从纱线成本拆分反推）：
  已知：32S 精梳棉纱 = 棉花 ¥15,300 + 加工费 ¥6,000 = ¥21,300
  
  棉花成本弹性 = 棉花在纱线中的占比 = 15,300 / 21,300 = 72%
  即：棉花涨 10%，纱线理论涨 7.2%
  
  但这不是需求弹性，是成本传导弹性
  需求弹性 = 面料厂采购量变化% / 纱线价格变化%

Obsidian 可用数据：
  纱线成本拆分 ✅（棉花深度报告）
  面料厂采购量 → 待补（柯桥指数可间接反映）
  → 需用柯桥指数代替采购量
```

### 边 ③→⑤：面料→成衣（采购弹性）

```
采购弹性 = 成衣厂采购量变化% / 面料价格变化%

计算方法：
  1. 柯桥面料指数月度变化（价格变量）
  2. 成衣出口量月度变化（海关 HS 61/62，采购量代理变量）
  3. 回归分析：出口量 = α + β × 面料指数
  4. β = 采购弹性

Obsidian 可用数据：
  柯桥指数 ✅（环节03已收集）
  海关出口 ✅（申洲/晶苑年报 + 海关数据）
  → 可以计算！
```

### 边 ⑤→⑥：成衣→品牌（倍率弹性）

```
倍率弹性 = 品牌采购量变化% / 成衣出厂价变化%

计算方法：
  已知品牌倍率：
    优衣库：零售价 = 出厂价 × 3.5（中位数）
    ZARA：零售价 = 出厂价 × 5（中位数）
    CHICJOC：零售价 = 出厂价 × 4（中位数）
  
  倍率弹性 = 1 / 倍率 = 出厂价在零售价中的占比
    优衣库：1/3.5 = 0.286
    ZARA：1/5 = 0.200
    CHICJOC：1/4 = 0.250
  
  含义：出厂价涨 10%，优衣库零售价涨 2.86%
  但这不是需求弹性，是成本传导弹性
  
  需求弹性 = 品牌采购量变化% / 出厂价变化%
  → 需用品牌订单量数据（Comtrade 进口量代理）
```

### 边 ⑥→⑦：品牌→渠道（渠道弹性）

```
渠道弹性 = 渠道销售量变化% / 品牌零售价变化%

计算方法：
  1. 天猫/抖音 GMV 月度数据（蝉妈妈/阿里财报）
  2. 品牌零售价变化（年报/电商平台价格监控）
  3. 回归分析：GMV = α + β × 零售价
  4. β = 渠道弹性

Obsidian 可用数据：
  天猫/抖音 GMV → 待补（蝉妈妈可查）
  品牌零售价 → 部分可得（电商平台监控）
  → 缺口：月度 GMV 数据
```

### 边 ⑦→⑧：渠道→消费者（需求弹性，最核心）

```
需求弹性（PED）= 消费者购买量变化% / 零售价变化%

这是最核心的弹性，也是最需要精确计算的

计算方法 1：从销售数据反推
  公式：PED = (ΔQ/Q) / (ΔP/P)
  
  示例：优衣库
    FY2026 H1 日本营收 +14.8%（量价拆分未知）
    如果假设价格涨 5%，量涨 9.8%（14.8% - 5%）
    → PED = 9.8% / 5% = 1.96（弹性很高）
    
  但这不对——优衣库的量价拆分不是这么简单的
  需要更精确的数据

计算方法 2：从行业数据回归
  数据：国家统计局 月度服装零售额（金额）+ 服装零售量（件数）
  公式：ln(Q) = α + β × ln(P) + ε
  β = 需求弹性
  
  Obsidian 可用：
    人均衣着消费 ¥1,479/年 ✅
    电商渗透率 35% ✅
    退货率 25% ✅
    → 缺口：月度零售量/零售额数据（国家统计局可查）

计算方法 3：从学术文献取值
  服装行业需求价格弹性研究：
    一般服装：-0.3 到 -0.8（中等弹性）
    快时尚：-0.5 到 -1.0（弹性较高，替代品多）
    基础款（优衣库）：-0.2 到 -0.5（弹性较低，刚需）
    高端品牌：-0.1 到 -0.3（弹性很低，品牌忠诚）
    运动品牌：-0.3 到 -0.6（功能性需求）
```

### 3.3 从国家统计局月度数据计算需求弹性

```
数据源：国家统计局 → 社会消费品零售总额 → 服装类

公式：
  ln(服装零售量_t) = α + β × ln(服装零售额_t/服装零售量_t) + ε
  
  其中：
    服装零售量_t = 月度服装销售件数（万件）
    服装零售额_t/服装零售量_t = 服装单价（元/件）
    β = 需求价格弹性

实操步骤：
  1. 国家统计局网站下载 2020-2026 月度服装零售数据
  2. 计算每月单价 = 零售额 / 零售量
  3. 取自然对数
  4. OLS 回归：ln(量) = α + β × ln(价)
  5. β = 需求弹性

预估结果（基于学术文献）：
  β ≈ -0.4 到 -0.6
  即：服装零售价涨 10%，销量降 4-6%
```

### 3.4 从品牌财报反推弹性

```
数据源：优衣库 FY2026 H1 财报

已知：
  日本营收 +14.8%
  门店数基本持平
  同店销售增长 ≈ 营收增长（假设无新开店贡献）

假设分解：
  营收增长 = 量增长 + 价增长
  
  如果价涨 3%（优衣库通常年涨 3-5%）
  → 量增 = 14.8% - 3% = 11.8%
  → PED = 11.8% / 3% = 3.93（异常高）

  但这不合理——优衣库的量价分解需要更精确数据
  实际上优衣库的 +14.8% 主要来自：
    - 日元贬值（海外营收折算 JPY 增加）
    - 海外门店扩张
    - 日本同店增长（量+价）
  
  更精确的做法：用日本本土同店销售增长单独计算
```

## 四、弹性系数的动态学习机制

### 4.1 从实时数据中学习

```yaml
# 每月自动更新弹性系数
elasticity_learning:
  # 数据采集
  data_sources:
    - source: "国家统计局月报"
      metric: "服装零售额/零售量"
      frequency: "monthly"
      
    - source: "海关总署月报"
      metric: "HS 61/62 出口量/出口额"
      frequency: "monthly"
      
    - source: "柯桥指数"
      metric: "面料价格指数"
      frequency: "weekly"
      
    - source: "品牌财报"
      metric: "同店销售/营收拆分"
      frequency: "quarterly"
  
  # 计算流程
  calculation:
    step1: "采集月度数据（价格 + 数量）"
    step2: "取自然对数"
    step3: "OLS 回归：ln(Q) = α + β × ln(P)"
    step4: "β = 弹性系数"
    step5: "计算 95% 置信区间"
    step6: "与上月系数对比，判断趋势"
    
  # 输出
  output:
    - "elasticity_monthly.md（月度弹性报告）"
    - "更新 Obsidian/_因果链条/因果边参数表.md"
    - "更新 causal_rules 中的弹性参数"
```

### 4.2 弹性系数的置信区间

```
弹性系数不是一个固定数字，而是一个范围：

  需求弹性 β = -0.45，95% CI = [-0.52, -0.38]

含义：
  有 95% 的把握，弹性在 -0.52 到 -0.38 之间
  最可能值是 -0.45

v3 的因果 DAG 应该用区间而非点估计：
  输入：价格变化 +10%
  输出：需求变化 = [-5.2%, -3.8%]（而非"降 4.5%"）
  
这比点估计更诚实，也更实用
```

> **核心结论**：
>
> 1. **能精确算的**（A+级）：棉花→纱线 0.72、PTA→涤纶 0.88——从 Obsidian 成本拆分直接算
> 2. **能合理估的**（A级）：面料→成衣 0.60、出厂→零售 0.25——从年报数据推算
> 3. **需要补数据的**（B级）：零售→消费者弹性——从国家统计局月度数据回归计算
> 4. **所有弹性都应该用区间**（-0.5 ± 0.15），而非点估计
> 5. **弹性是动态的**——每月从实时数据重新回归更新
